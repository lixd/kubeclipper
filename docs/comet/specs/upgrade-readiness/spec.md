# 升级行为规格

落实用户已确认的升级修复方案。用户在完整方案后明确回复「[$comet] 那就按计划修复吧」，权限恢复后要求「继续」。

# 范围

修复 Agent 单组件升级误报，限定 Kubernetes 升级起点为 v1.36.4，并实现单节点可中断维护升级。沿用当前修复分支，作为一个 change 顺序完成，相关升级状态、接口与实机验收紧密关联。

## 目录结构

### 修改

- pkg/cli/upgrade 负责 Agent 实际版本、服务健康与 Server 版本校验范围。
- pkg/scheme/core/validation 负责 CLI/API 共享的升级源版本边界。
- pkg/apis/core/v1 负责单节点维护模式参数和升级准入。
- pkg/scheme/core/v1/k8s 负责单节点排空、升级、恢复调度、实际版本校验及失败重试。
- pkg/cli/cluster 与 Console 升级入口负责明确的维护模式及中断影响提示。
- 对应回归测试和升级说明覆盖正常入口与失败恢复。

# 关键决定

1. Kubernetes 升级源版本最低 v1.36.4。v1.35.8 保留安装、物料和日常管理；其升级请求在创建任务和修改节点文件之前拒绝，提供可读原因。
2. 单节点维护模式明确允许中断，使用 drain --disable-eviction 时提示会绕过所有受影响 Pod 的 PDB，包含业务 Pod。多节点使用正常驱逐保护。API、CLI、Console 的用户行为一致。
3. 升级前核对拓扑、Pod、PDB、集群健康和备份条件；失败后记录控制面、kubelet 实际版本，重试收敛，恢复节点原有调度状态。
4. 仅在升级包含 Server 时对比平台 API 目标版本，Agent 检查自身二进制和服务健康。
5. 验证仅使用 sh-dev-3 和 sh-dev-4，保护 sh-dev-2 及其他业务服务。资源密集检查优先 sh-dev，精确同步候选源码。
6. 当前 containerd/Calico 版本组合沿用本次已确认的有限环境支持范围，上游推荐范围差异作为已知限制记录。正式发布、接受归档仍遵循实际用户授权。

# 非目标

本轮范围不包含 containerd 1.x 至 2.x 迁移、修改发行组件版本及正式版发布。

# 验收示例

- 旧 Server 下单独升级两台 Agent，命令成功，Agent 实际目标版本且服务健康，重复执行成功。
- CLI 和 API 对低于 v1.36.4 的升级请求返回清晰原因，零升级任务与节点文件变更，v1.35.8 安装和管理可用。
- 单节点维护模式通过 API/CLI/Console 明确提示中断和全部 PDB 绕过影响，默认调用保留保护并清晰拒绝无法完成的排空。
- 单节点 v1.36.4 升至 v1.37.0 后控制面、kubelet 实际版本一致，Calico 与系统 Pod 恢复 Ready，API 和业务探针正常。
- 升级失败保留可观察的实际状态，原生重试可完成目标升级，调度状态恢复且多节点保留 PDB 驱逐语义。
- sh-dev-3 和 sh-dev-4 在线及离线升级复验通过，所有最新 Operation Task 成功，测试后恢复原 Registry 和其他业务服务，保护 sh-dev-2。
