## 一、缺陷与修复

### 根因

- 授权唯一入口 `pkg/authorization/rbac/rbac.go getRoleReferenceRules` 只返回
  `globalRole.Rules`，从不读 `kubeclipper.io/aggregation-roles` 注解；注解展开仅存在于
  IAM 角色 create/update API（`pkg/apis/iam/v1/handler.go` CreateRoles/UpdateRole）。
- 内置角色由 `migrateRole` **仅创建不重建**（server.go），`UpdateRole` API 又拒绝修改
  `kubeclipper.io/internal` 角色——因此存量库中 `cluster-manager` 等内置角色永远只有
  base rules，数据侧无法自愈，只能授权期展开。
- 上游 master 同样存在此缺陷（该区域字节级一致）；本分支 `pkg/authorization/` 相对上游
  零分叉，修复可直接上游化。

### 修复（commit `136882c4`）

- `pkg/models/iam/aggregation.go`（新）：`FetchAggregationRoles` 共享 helper——原样下沉
  handler 的模板解析逻辑（注解 JSON 解析失败→error；模板 NotFound→warn 跳过；其他错误→
  error），IAM handler 改为薄委托，授权侧与 API 侧共用。
- `pkg/authorization/rbac/rbac.go`：授权期把聚合模板规则与角色自身规则取**并集**（内置
  角色的设计意图即 base+模板；RBAC 纯 allow 模型下重复规则无害）；单层展开与 handler
  现行为一致（模板不再聚合，无环风险）；模板解析失败/注解格式错→warn 降级为仅 base rules
  （授权链路优雅降级，不因注解问题整体失败）；per-request `roleCache` 去重同请求内重复
  角色读取。**不加跨请求缓存**：保持权限变更即时生效的现有语义。
- 高频路径零影响：agent 角色 `kubeclipper-agent-operation-v2` 无聚合注解（直接 rules），
  agent 流量不产生任何额外读取；仅带聚合注解的角色的请求多 N 次 GetRoleEx（KubeSphere
  同型生产实现）。

### 单测

- `rbac_test.go`：mock 补齐被聚合引用的模板角色 stub（原 mock 返回"已展开"形态，恰好
  掩盖了缺陷）；新增回归——**mock 返回未展开形态的 `cluster-manager` → 访问 backuppoints
  应 Allow**（修复前必失败）；负向：view-only 模板不授予写权限；新增
  `TestAuthorizer_Authorize_MissingAggregationTemplate`——模板缺失时降级为 base rules、
  不报错。`pkg/authorization`、`pkg/models/iam`、`pkg/apis/iam/v1` 及 server/models 全部
  测试通过，`go build ./...` 通过。
