## 验收范围与计划

本case测试普通密码登录，以及启用MFA后的验证码认证链路。现有`fake_sms`只将验证码写入服务日志，**真实短信送达不在本case范围**。此前将真实短信provider/收码环境列为阻塞条件，扩大了原始验收范围，现予以纠正。

1. 从当前代码构建真实Server，在临时服务、独立端口和独立etcd前缀下启动；验证密码登录和错误密码拒绝。
2. 建立临时用户，启用fake_sms MFA，验证challenge、取码、错码、登录、token真实API访问、验证码一次性和重发限流。
3. 使用真实时间等待65秒，分别验证重发窗口结束和验证码过期；验证过期后申请新码能登录。
4. 停止临时服务、删除测试存储前缀及临时配置，检查原平台服务和共享Registry；更新case与台账。

## 下次执行前置条件

先测试MFA默认关闭时的密码登录，再为隔离服务增加：

```yaml
authentication:
  mfaOptions:
    enabled: true
    mfaProviders:
      - type: fake_sms
        options:
          ttl: 60s
```

临时用户需有`phone`字段，用于验证码与限流缓存键；可使用测试值，无需可收短信的手机号码。调用`POST /oauth/login`取得428中的provider，再调用`POST /oauth/verification-code`，从隔离服务journal取码。验证码登录使用`POST /oauth/token`表单：`grant_type=mfa`、`mfa_provider=fake_sms`、`token`、`code`。验证码TTL和发送间隔都实际等待，不改系统时钟或伪造缓存时间。此case无需代理。
