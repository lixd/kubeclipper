# KubeClipper 测试用例审查与整理

本次先审查清单，暂停后续实机测试。本文记录测试设计结论，不是发布验收通过报告。

核对对象：后端 `fe0b59fe`、配套 Console `2169a475`、当前 API/CLI、发布物料清单、Go E2E 及历史测试台账。当前支持策略仍包含 Kubernetes 1.35.8 的安装管理；升级起点为 1.36.4。先前确定的登录证书验证处理方式不在本次修复范围。

## 结论

现有台账覆盖面较广，但把功能、入口、内部机制、发布工程和历史执行结果放在了一起。需要去重、分级，并补齐核心结果断言。

- 原台账共有 194 个编号，包含 1 个早先合并的编号和 2 个退役编号。历史轮次按当时的统计和编号查证。
- 第一轮归并 14 个编号后有 177 项有效用例。本轮逐项按发起动作、可观察结果和前置条件再归并 23 个编号，现行目录有 **154 项有效用例**，其中 **P0 89、P1 50、P2 15**。
- 历史 ✅、当前候选通过、已实现自动化是三个不同字段。当前清单不能直接充当新候选的通过证明。
- 当前 Go E2E 入口只注册 cluster/node/region 共 16 条 spec；数量与完整台账没有一一对应关系。
- 3 项 P1 调整为 P2，6 项改用 Go 契约优先，复用已有集群或现有测试夹具取证。故障恢复、权限边界、实际数据和发布制品仍各有通过判据。

全部编号的建议见[逐项分级表](testcase-inventory-2026-11-19.md)。该表是后续测试设计，不继承历史通过状态。

### Console 的 `4-07` 应拆成明确检查点

保留父编号，至少分别登记：登录与角色可见性；建群向导参数与真实结果一致；节点/拓扑和版本展示；升级确认及单节点停机提示；备份/恢复；Operation 进度、失败原因、取消与重试；kubeconfig 下载及实际使用；注销外部集群后原集群仍正常。

后端 Go E2E 负责同一操作的真实结果，浏览器负责点击、表单、提示和展示。只打开登录页不能代表整个 Console 通过。

| P0 发布必测 | 对本次明确承诺的能力执行；失败、阻塞或未执行不能写通过 | 安装交付、建群和网络、扩缩/转换、升级/PDB、备份恢复、删除、关键权限、操作状态一致性、发布物料绑定 |
| P1 常规回归 | 全量回归执行；对应模块有改动或发布明确承诺时升级为门禁 | NFS、S3/定时备份的附加边界、OIDC/MFA、外部纳管、终端/exec、诊断、缓存及专项网络配置 |
| P2 专项或轻量检查 | 适合契约测试、构建检查或周期专项；不为每项重建集群 | completion、普通查询格式、模板/DNS 的完整 CRUD、feature-gates/ignore-preflight 等高级参数、退役入口扫描、容量压测 |

分级表示执行频率和风险，不表示允许忽略安全边界。例如模板可低频回归，但模板密码泄漏仍由 P0 的敏感信息检查拦截。

- 版本矩阵按实际 support policy 生成，当前三个默认组合为 `1.35.8/1.7.29/3.29.6`、`1.36.4/2.2.4/3.31.5`、`1.37.0/2.2.4/3.31.5`；不要把所有版本做无意义的笛卡尔积。非法组合由准入契约和负向 API 检查验证。
- 先确认架构、OS、Registry、网络模式、认证方式及拓扑等发布配置。缺 ARM64 环境只能写未验证；若发行声明支持 ARM64，就需要相应真实消费验收，不能用构建成功代替。
- 当前三节点可覆盖 1M2W、3M0W 和多数生命周期；不能把它等价成 3M 加独立 Worker 的组合故障验收。该组合如进入发布承诺，应增加适合的独立节点/VM。
- `nvidia-dra-driver-gpu` 和 `nvidia-gpu-operator` 当前物料配置为 disabled，不新增 GPU 安装验收作为本轮缺失核心功能。
- 高并发容量测试要先有容量目标及环境；报告应记录环境约束及实际并发数。

## 4. 整理后的执行主线

| 主线 | 组合后的实际场景 | 主要方式 |
|---|---|---|
| J01 交付 | 国外在线、国内在线、真实离线，各完成取 CLI→Registry→平台→join→建群 | Go E2E + SSH/网络隔离准备 |
| J02 平台 | 单 Server、分离 Agent、三 Server HA、重启、clean/redeploy、已有资源上的平台升级 | Go E2E + SSH |
| J03 集群 | 支持组合的 AIO/1M1W/3M0W，实际健康和网络、准入正负对照。批量 Worker 加入或多目标 Task 变更时加跑 1M2W 冷建 | Go E2E + Kubernetes client |
| J04 节点 | Worker/Master 增删、转换、Agent 注销重入、身份/心跳、节点复用 | Go E2E |
| J05 升级 | 多节点无损路径、单节点维护路径、失败恢复、版本下限、证书更新 | Go E2E + 连续业务探测 |
| J06 备份 | FS/S3、marker 回滚、定时/轮转、坏备份、删除存储对象 | Go E2E + 真实存储 |
| J07 删除 | 正常/安装失败/删除失败重试、备份保护、宿主机清理 | Go E2E + SSH |
| J08 操作 | cancel/retry/CAS/幂等/日志/分页/超时/重启恢复、跨集群隔离 | Go 集成测试 + 关键实机 E2E |
| J09 权限 | 用户角色、登录/token、敏感字段、Agent 和代理等入口的权限边界 | Go API E2E；可选 IdP 独立环境 |
| J10 NFS | 安装→真实 PVC Bound→写读→卸载和清理、失败 retry | Go E2E + 真实 NFS |
| J11 管理 | 模板/DNS/设置/Registry 配置、外部纳管及安全注销 | Go API E2E + 关键真实消费 |
| J12 Console | 按检查点执行真实用户操作，关联后端结果 | 浏览器 E2E |
| J13 CLI | 参数传递、交互/非交互、输出/错误码 | 复用上述主线 + 轻量 CLI 检查 |
| J14 发布 | 物料、架构、来源、不可变性、qualification 与 acceptance 绑定 | 发布流水线 + 从实际产物运行主线 |

14 条主线组织实机操作。154 项有效用例按实际入口和变体记录各自断言，多个编号可以引用同一候选的同一轮证据。

## 5. 后续实现顺序

1. 以本次逐项表确定活动范围、分级和上述核心断言，历史报告继续单独保留。
2. 建立编号→Go spec/浏览器用例→实际证据的对应关系。优先补 NFS、升级/恢复真实结果、终端和重复升级流程等已有问题。
3. 为建群、扩缩、升级、备份、删除建立可复用的真实环境 fixture；每次危险操作绑定 UID，失败也清理本轮资源，保留失败证据。
4. 实机执行前确定候选 SHA、物料 manifest、发布配置和前置条件。Skip/Blocked/未实现分别登记，不能用旧轮次结果填充。
5. 然后才恢复测试。当前整理工作不重写产品实现、不扩大已承诺的版本/架构范围。
