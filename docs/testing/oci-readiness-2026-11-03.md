# OCI 交付与生命周期修复（2026-11-03）

基线为用户 fork `lixd/kubeclipper` 的 `oci` 分支 `71319775621cb0a0f105ff6a599a275f85c23d5b`。前端使用用户 fork `lixd/console` 的 `ee51883a2126324a567fa17cb1020e39916d17aa`，本轮没有修改前端源码。所有提交和测试制品只进入用户 fork，不向上游提交或发布稳定版本。

## 修复

- Console 包版本调整为 `v1.6.1-oci.ee51883`，固定上述前端提交，包含统一 Registry 选择及升级仅发送版本的实现。工作流默认检出同一 owner 的 Console 仓库，保留显式仓库变量和归档 revision 校验。旧版本制品不覆盖。
- CLI 一次创建命令复用同一份成功的组件元数据；查询失败不缓存。服务端按 Registry 与规范化仓库集合缓存策略索引，复用已有五分钟 TTL，合并并发请求；等待可取消。强制刷新有独立入口，失败不会变成成功缓存。
- `checkHealth` 冷启动窗口从十分钟调整为三十分钟。每轮同时检查节点和系统 Pod，要求 Ready 条件，拒绝空列表；记录阻塞容器、镜像和等待原因，超时保留最后观察及取消/截止错误。没有关闭 HTTP/2，没有改写失败 Task 或增加镜像源回退。该调整不解决外部 GHCR/CDN 的带宽或连通性问题。
- Calico 生成真实卸载 Agent 步骤，在全部目标节点执行。清理 `cni-*` 命名空间、Calico 隧道/veth、KUBE-/cali- 链及其引用；使用不清空宿主表的删除事务，兼顾已加载的 legacy 规则。失败明确返回，dry-run 不修改网络，重复执行安全。取消全表 iptables flush，不再卸载共享 IPIP 内核模块。CNI 数据清理修正到实际目录。
