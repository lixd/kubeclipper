## 一、修复（commit `5ce8f2dc`）

### 根因（三层叠加）

1. `deployKCAgent` 把外部主机写入 deploy-config agents 列表时 `Metadata{Region: region}`
   **不带 AgentID**（`pkg/clustermanage/kubeadm/provider.go` 两处 add 点）；
2. 外部集群删除侧的清理以 `Agents.ExistsByID(nodeIP)` 为门——无 ID 条目永远匹配不上；
3. 该路径内的 `Agents.Delete(ip)` 实际按 **agentID 反查 IP**（`idToIP`），传入 IP 语义
   双重错位——即使条目有 ID 也删不掉。

后果：孤儿条目永存；`kcctl upgrade agent` 的目标列表来自 deploy-config agents
（`upgrade.go hostsForRole`），把已移除的外部主机当 agent 目标并在其上中断（R40 实测）。

### 修法

- 两处 add 点写入 `AgentID: node.ID`（记录已知身份；见 §三 说明）；
- 删除门 `ExistsByID(nodeIP)` → `Exists(nodeIP)`（按 IP 键，旧格式无 ID 条目也能命中）；
- "del" 分支改用新增的 `Agents.DeleteByIP(ip)`（`cmd/kcctl/app/options/options.go`），
  不动 `Delete(id)`（drain 流程合法地按 ID 使用它）；
- 单测 `TestAgentsAddExistsDeleteByIP`：Add/Exists/ExistsByID/DeleteByIP/Delete 语义矩阵，
  显式覆盖"无 AgentID 的旧条目按 IP 可删、不受删其它条目影响"。
- `go build ./...` 与 cmd/pkg 相关包测试全绿。
