## 本轮修复与验收

### SemVer 候选选择

`rc.26` 曾被旧版本比较逻辑排在 `rc.9` 后。fork 改用现有 SemVer 库比较 prerelease；旧逻辑先由新增回归用例复现失败，再由修复通过。定向 Go 测试通过；生成的三个 linux/amd64 二进制均报告版本 `v2.0.3-rc.28`、提交 `818377bc`、clean tree。三台 server 升级成功，API 报告版本与 revision 一致。

### PlatformSetting（4-15）

R31 检查发现 `/api/config.kubeclipper.io/v1/template` 的 GET/PUT 原样返回 Registry 密码；GET 后用空密码 PUT 还会清空存量凭据。修复后 GET/PUT 响应遮蔽密码，同 Host 的空/省略密码更新保留存量值，非空新密码仍会更新。新增 HTTP handler 回归测试：旧实现下失败，修复后通过。

rc.28 live 验证使用随机 canary，输出只记录状态与真假值：PUT、GET、空密码 PUT 响应均未回显 canary；`kc-server` journal 未发现 canary；最后恢复原始 PlatformSetting 快照且 GET 与快照一致。已有 R31 实测还覆盖：用户创建与详情响应不返回用户密码；无角色用户对 template GET/PUT 和 terminal key GET/POST 均 403；创建的临时用户删除后 GET=404；管理员 `GET /terminal.key` 不返回私钥，POST 后公钥变化，轮换后 GET 仍隐藏私钥。临时用户与设置已恢复；探针运行时生成的 mTLS 文件已删除。
